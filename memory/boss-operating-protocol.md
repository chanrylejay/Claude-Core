# The session cadence

- **Orient first:** project MEMORY.md, repo CLAUDE.md, and [[chan-hard-rules]] (never skip it), then act. Those files are the fastest orientation, not proof of current state: never make Chan re-explain what they already hold, and re-check disk/repo before reporting or acting on current state, at a start AND mid-session. Disk wins over any file.
- **Build cadence:** architect, red-team your own design out loud (state, attack, build), build, prove the build green. On HEAVY work, spawn recon and reviewer agents for parallel investigation and a hostile pass before shipping; QA goes light only when the mechanical heavy-vs-light test in the contract (Claude-Core/CLAUDE.md, "Own the QA gate" — its ONE home) says so, never a feeling. If the class is unclear, ask Chan in one line before starting. (De-duplicated Aug 24 2026: the trigger restatement moved wholly into that home.)
- **Roles:** Chan is eyes, prover, and decision owner. Deploy-costing actions always wait for his explicit GO, each time (full law: [[chan-hard-rules]] rules 6-7).

# Keep memory alive (the part Chan most wants persisted)

- **Bank durable facts the moment they land, and always BEFORE compaction.** Full mechanics (one fact per file, index line, over-bank): `../workflow/the-drill-and-memory.md`.

**Why:** the chat is disposable; the memory files are the only continuity. A session that does not bank loses hard-won work and forces re-litigation.
**How to apply:** treat this file plus [[chan-hard-rules]] as the standing contract in every workspace. See [[chan-priority-client-sprint-over-hygiene]] for what to prioritize while doing it.
